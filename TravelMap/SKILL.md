# 城市兴趣点地图数据制作

流程：**定受众 → 定标签 → 收集地点 → 取坐标 → 收集评价 → 写数据文件 → 校验**。

## 一、数据契约

### 城市对象

| 字段 | 说明 |
|---|---|
| `center` / `zoom` | 地图初始中心与缩放级别。坐标系与 `tiles` 源一致——国内 GCJ-02、境外 WGS-84，见第四节 |
| `attribution` | 底图版权署名 |
| `tiles` | 可选。覆盖默认（高德）瓦片源，**境外必填**，见第四节。URL 不能带 `{s}` |
| `updated` | 数据核验年月 `YYYY-MM` |
| `spots` | 地点数组 |

### `spots[]` 每条

**必填**

| 字段 | 说明 |
|---|---|
| `id` | 唯一键，**只含字母数字**（会进 DOM 属性与查找表） |
| `name` | 显示名 |
| `lat` / `lng` | **坐标**。坐标系随该份数据的底图源——国内 GCJ-02、境外 WGS-84，见第四节 |
| `tags` | 数组，`[0]` 是主标签**决定地图图标**，其余标签在彩色环上各占一段 |
| `area` | 地区与交通。约定用 `·` 分隔主区与交通，列表只取 `·` 前段 |
| `hours` | 开放时间。补充说明放全角括号里，列表只取 `（` 前段 |
| `fee` | 票价。多档位用 `；` 分隔，列表只取第一段 |
| `intro` | 简介。列表限两行，详情全文 |
| `kind` | `"review"` 或 `"facts"`，见第五节 |
| `pros` / `cons` | 优点 / 缺点数组 |

> ⚠️ **`area` / `hours` / `fee` 是列表卡片的展示契约，不是备注栏。**
>
> 卡片上只显示第一个分隔符**之前**的那一小段，其余部分只在详情面板出现：
>
> | 字段 | 卡片取到哪个分隔符为止 |
> |---|---|
> | `area` | `·` |
> | `fee` | `；` `;` `，` `,` |
> | `hours` | `（` `(` `；` `;` |
>
> 所以这三个字段的**第一段要写成能独立读懂的短摘要（10 字以内）**，档位、淡旺季、预约要求等细节一律放到分隔符之后。写成什么样：
>
> | 字段 | ✗ 整段连着写 | ✓ 摘要 + 分隔符 + 细节 |
> |---|---|---|
> | `area` | 地区详细地址与交通全写在一起 | `地区 · 详细地址；交通` |
> | `fee` | 全部票种档位连着写 | `最低价 起；票种一 价格／票种二 价格／…` |
> | `hours` | 淡旺季时段连着写 | `主要时段（淡季时段、停止入场等说明）` |
>
> **注意 `fee` 的分隔符集合不含全角括号**，`免费（需预约）` 不会被截断，要写成 `免费；需预约`。

**可选**

| 字段 | 说明 |
|---|---|
| `rank` | 推荐徽章文本。**有值即视为推荐位**，会加徽章与图标光晕，因此应保持稀缺 |
| `src` | 来源说明。`kind="review"` 时**必填** |
| `srcLinks` | 来源链接 `[{t:"显示名", u:"网址"}]` |
| `url` | 官网地址 |

### 标签

- 每个标签 = **图标 + 颜色**：图标定义在逻辑层（`app.js` 的 `ICONS`），颜色定义在样式变量里（`main.css` 的 `:root`）。图标取自 **lucide**（ISC 许可），按名内联，不引整包、不用 emoji。
- 加标签分三种情况，**改动面差很多**，先看清楚属于哪种再动手：

  | 情况 | 要改哪里 |
  |---|---|
  | 复用**已有**的图标名与颜色变量 | 只在该城市的 `extraTags` 里加一条，`app.js` 与 `main.css` 都不用动（挂载时按城市合并：`TAGS = Object.assign({}, DEFAULT_TAGS, data.extraTags \|\| {})`） |
  | 要**新图形**或**新颜色** | **同时改两处**——`app.js` 的 `ICONS` 加图形、`main.css` 的 `:root` 加颜色变量 |
  | **多个城市共用** | 提到 `app.js` 的 `DEFAULT_TAGS`，不要每个数据文件各写一遍 |

- **两处缺任何一处都是静默失败**，页面照常渲染，只是「颜色不对」或「图标没了」：颜色变量查不到 → 退化成默认灰 `#8a8a9a`；图标名在 `ICONS` 里查不到 → 渲染出一个不含图形的空 `<svg>`。
- 标签集合随受众变，没有固定清单。

## 二、定受众与标签

**受众决定标签集合，不是反过来。** 每类要有明确的入选标准，否则收集时会反复犹豫、数据混杂。

> ⚠️ **受众定位会和数据可得性打架。** 受众最关心的那类往往是最难采的那类：大众地标覆盖率高、名称规范、坐标好拿；小众业态（新开业、非连锁、近年改名的店）在地图数据里常查不到，名称还随运营方变。开工前先想清楚，如果某类必须达标，就预期在这类上花掉大部分时间，并准备替代取坐标手段（官网、公众号、平台门店页）。**收不齐就如实呈现数量差异，不要凑数**——分类的可信度比数量重要。

## 三、收集地点

> ⚠️ **把收集工作分派给他人或检索代理时，必须连字段书写约定一起交代。**
>
> 只说「要开放时间、票价、地区交通」，拿回来的一定是一整段叙述：完整地址接交通、按淡旺季分段的开放时间、全部票价档位连着写。这些内容本身没错，**直接入库却会撑破列表卡片**（见第一节的数据契约）。分派时把三个字段的书写约定一并写进任务说明，能省掉一整轮返工。

- 按标签**逐类检索**；用目标受众的行话，命中率远高于通用词。
- **硬性核验**三项：是否仍在营业（结业/搬迁）、是否已开业（预告与实际不符）、时间敏感项（展会、市集、季节性活动的档期每年变，必须查当年公告）。
- 攻略源时效性差：**被推荐的冷门地点，单独搜一次「名称 + 关闭 / 停业 / 现状」**。热门地标不必。

## 四、取坐标

**铁律：数据坐标系必须与底图瓦片一致。** 国内瓦片源（高德、腾讯等）为 **GCJ-02**，数据就只存 GCJ-02。（境外**正相反**，见本节末「境外」小节。）

- **最稳的路径**是用**高德坐标拾取器**逐点取，拿到的直接就是 GCJ-02。
- 点多了嫌慢，可在 **OSM** 批量取 WGS-84 再**离线转换**，代价是必须做下面三道检查。
- 转换在写入数据文件**之前**完成。**不要在页面代码里留一个「看起来该被调用」的转换函数**——后人顺手调用会导致偏移叠加两次；换瓦片源等于换坐标系，需全量重转。
- **自检**：取一个已知地标，把数据坐标与该地标在 OSM 的 WGS-84 值比。相差数百米且方向一致 ⇒ 已正确转换；只差几十米 ⇒ 混入了未转换的数据。

### 境外（中国以外）：坐标系与底图

**GCJ-02 的偏移只存在于中国境内。** 境外地点直接用 WGS-84（GPS 原始坐标），**不要做任何转换**——转了反而错。

底图随之要换，因为**高德瓦片在境外基本是空白**：实测同一接口同一缩放级别，北京 z10 返回 19801 字节的正常瓦片，悉尼 z8／z12 只返回 **179 字节**的占位图（z5 那 3–4 KB 基本只是海洋底色）。境外数据必须用 `tiles` 字段换源。

| 底图源 | URL | 说明 |
|---|---|---|
| **Esri 街道图** | `https://server.arcgisonline.com/ArcGIS/rest/services/World_Street_Map/MapServer/tile/{z}/{y}/{x}` | **首选**。无需 key，带 Referer 与不带 Referer 都正常出图。同域另有 `Canvas/World_Dark_Gray_Base`（深灰，适合深色站点）、`World_Imagery`（卫星）、`World_Terrain_Base`（地形）。**注意路径是 `{z}/{y}/{x}`，y 在前**。署名 `© Esri, HERE, Garmin, © OpenStreetMap contributors, and the GIS user community` |
| OSM 标准 | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | **不要用于 `file://` 打开的页面。** 观感好、无需 key，但志愿者服务器按使用政策拦截：本地双击打开时浏览器不发 Referer，会被返回一张 `Access blocked` 图。用命令行抓反而正常，所以这个坑只有真在浏览器里打开才暴露。署名 `© OpenStreetMap contributors` |
| Carto 暗色 | `https://basemaps.cartocdn.com/dark_all/{z}/{x}/{y}.png` | 观感最贴合深色站点，但**已要求 API key**，见下 |

**URL 不能带 `{s}`。** 默认底图模板是 `https://webrd0{s}.is.autonavi.com/...`，`{s}` 由 `app.js` 里写死的 `subdomains: ["1","2","3","4"]` 填充——Leaflet 取 `subdomains[|x+y| % 4]`，即替换成 `1`／`2`／`3`／`4`，与 `webrd0` 拼成 `webrd01`…`webrd04`。

换其他源时主机名并没有这种 `0N` 子域，若照抄成 `https://{s}.basemaps.cartocdn.com/...`，`{s}` 只会变成 `1`，拼出 `1.basemaps.cartocdn.com` 这种无法解析的主机。**写不带 `{s}` 的主机名即可，不必改 JS。**

**Carto 已要求 API key，不要再选它。** 现行条款是每月 500 万次请求内免费、但须申请 key（免费、无需账号）；无 key 的 `basemaps.cartocdn.com` 是旧端点，**它不报错**，而是返回一张写着 `API KEY REQUIRED` 的占位图——**HTTP 200、内容类型仍是 image/png，只看状态码完全正常**。

> ⚠️ **这类失效是「部分」的，最难第一眼归因。**
>
> 它只对**未命中缓存**的瓦片返回占位图：热门城市（如悉尼 CBD）正常，冷门区域（内陆、海面）与低缩放级别（全国视野）大面积报错。实测某次默认视野 3×3 的 9 格里有 3 格是占位图——页面上就是半屏 `API KEY REQUIRED`；换个时间重开还可能因缓存变化而表现不同，极易被误判成网络问题。
>
> **自检方法**：按最终视野批量抓 3×3 瓦片，**逐格看清图形内容**。纯色海洋格本来就是小图，**不能用「体积小」当判据**，必须真看图。
>
> **别指望页面上的自动检测。** 占位图（`API KEY REQUIRED`）和封禁图（`Access blocked`）**都是 HTTP 200 的图片**，会正常触发 `tileload`、不触发 `tileerror`——页面里的瓦片成败统计只能发现网络层失败（域名解析不了、连接被拒），对这两类完全无效。**交付前自己抓图看是唯一可靠的办法。**

**境外取坐标的主要失手方式是同名错配**（国内则主要是「查不到」）。查询串要带上上级行政区：`Barossa Valley` 会命中巴拉瑞特市内一条叫 Barossa Drive 的街道（维多利亚州），换成 `Barossa Valley, South Australia` 才命中南澳的产区。国界框挡得住跨州错配，**挡不住同州同名**，所以逐条读 `display_name` 里的行政区仍是必需的。

### 三道检查，缺一不可

1. **经纬度边界检查**（机械，必须做）——坐标必须落在目标区域的经纬度框内。**错配不会报错，只会安静地返回别处的坐标。**
2. **人工核对返回的地点全名与行政区**——范围限制只保证结果在范围内，**不保证是对的 POI**。同城错配最隐蔽：边界检查会放行，坐标看着也像那么回事，但标记落错了区。
3. **抽样反查**（收尾）——挑 2–3 个你熟悉的地标，把最终坐标与权威值比对。

### 查询要点（用 OSM 的 Nominatim）

| 做法 | 说明 |
|---|---|
| ✅ 用目标语言的**纯地名**查询 | 命中率最高 |
| ❌ 别混合「多语言 + 城市名」 | 这类查询串命中率极低，且**返回空数组而非报错** |
| ✅ 准备**名称变体回退** | 简称查不到时换全称/官方名 |
| ✅ 加 `viewbox` + `bounded=1` 限定范围 | 能挡跨区错配，**挡不住同区错配** |
| ✅ 设 `accept-language`、请求间隔 ≥1 秒、带自定义 `User-Agent` | 尊重服务方限流 |

### 查不到时的两条退路

部分中国 POI 在 OSM 里**完全没有记录**。别硬凑：

1. **换名称变体**（全称、官方名、带/不带「国家」「市」）。
2. **用地标代理点**——取一个紧邻且已收录的地点，误差百米级对旅游地图可接受。**代理点必须在自己的记录里标明是代理**，别让它看起来像精确点位；代理多了误差会累积成系统性问题。

## 五、收集评价与来源

### `kind` 判定

| `kind` | 徽章 | 含义 | 详情标题 |
|---|---|---|---|
| `"review"` | 评价有据 | 优缺点来自**检索到的评价**，`src` 必须写明出处 | 网络评价 |
| `"facts"` | 客观信息 | 票价、时间、交通等**客观信息**梳理，非用户评价 | 特点 |

判定很简单：优缺点出自检索材料 → `review` 并写来源；只是从官方/公开信息整理的客观特征 → `facts`。

### 评价是最难采的一环

**通用网页搜索基本拿不到可引用的评价原文**——返回的多是「必去十大」「攻略」这类标题，点进去是二手转述或广告，没有可署名的原话。有效得多的路径：

1. **本地媒体的实地报道**——记者采访的消费者原话可直接引用且署名清晰，还常带运营方提供的数据。
2. **点评平台的详情页**——评价原文集中，但注意平台条款与转载限制。
3. **用户痛点类报道**（同质化、真假混卖、溢价、设施不足）——作为 `cons` 往往比泛泛的好评更有价值。

> **铁律：宁可留空，不要编造。** `pros` / `cons` 可以省缺；没有可靠来源就不要标 `review`。编一条像模像样的好评比留空糟糕得多——前者是不可发现的伪造，后者只是数据不全。

### 平台来源与 WAF：实测口径（2026-09，境外）

- **点评平台（TripAdvisor 等）对脚本一律 403。** 链接在浏览器里能打开、`curl` 验不过，其条款也不允许转载评语。做法：评价内容**只做转述**并标注平台，链接**不进 `srcLinks`**——验收要求「所有链接实测可访问」，403 的就不该放进去。若某条的可用来源只剩平台，把 `src` 写成「以下优缺点整理自公开点评平台的访客反馈，暂未附可验证的链接」，而不是硬塞一个验不过的链接。
- **`.gov.au` 不等于可达。** 实测 `nt.gov.au`、`rottnestisland.com`、`ria.wa.gov.au`、`broome.wa.gov.au` 全部 403。官网字段必须逐条 `curl`，被挡时改指**同一辖区的官方机构页**：北领地公园改指 `northernterritory.com`，罗特尼斯岛改指 `westernaustralia.com`，都是实测 200 的官方旅游机构站。
- **最有价值的一档是本地媒体的实地报道**（ABC、The Age、SMH、The Guardian、BBC）：实测 200、署名清晰、可追溯性最好。旅游博客与内容农场（`*-expert`、个人攻略站）排最后，只在没有更好来源时用。
- 收录前把 `http://` 换成 `https://`（确认 https 版本可达时），别让数据里混着非 https 链接。

## 六、收集链接

**官网（`url`）：必须逐条实测，不要凭印象填域名。**

```bash
curl -sL --max-time 15 -o /dev/null -w "%{http_code}" "<网址>"
```

只写返回 200 的。注意两类误判：真实域名常与直觉不同（`.org.cn` 而非 `.com`），候选域名也可能根本无法解析；另有站点对非浏览器请求返回 **403/412**（WAF 拦截），域名存活但脚本验不过，需单独判断。字段是「如有」，**填一个打不开的链接比留空更糟**。

> ⚠️ **别自己加浏览器 UA。** 这条坑是实测出来的：`parks.vic.gov.au` 对**浏览器 UA 的脚本请求返回 403，对 curl 默认 UA 返回 200**；`parks.qld.gov.au` 恰好相反（默认 UA 403、浏览器 UA 200）。上面那条命令**不带 `-A`**，就照原样用。稳妥做法是**两种 UA 各试一次，任一为 200 即算可达**。
>
> ⚠️ **政府站会限流，403 可能是暂时的。** 一轮里连测上百条链接时，`parks.qld.gov.au`、`aph.gov.au` 会在 200 与 403 之间反复跳；同一个 URL 隔几分钟重测就恢复。所以 403 不要立刻判死，**隔一会儿单独重测一次**再决定；确认可达的可以手工记进实测结果，别让限流误伤正规官网。

**来源链接（`srcLinks`）：** `review` 条目补上实际检索到的出处 URL；`facts` 条目通常没有可追溯的具体出处，不渲染链接块。

## 七、写数据文件

### 格式约定

- **自注册**成 `(window.CITY_DATA = window.CITY_DATA || {})[<id>] = { ... }`。用带键的形式而非直接覆盖全局对象，并发加载时才不会互相覆盖。
- **不要有函数、DOM 操作、CSS、HTML 标签。**
- **字符串里不要出现 `<` `>` `"`**——渲染走 `innerHTML`，这些字符会破版甚至注入。需要引号用 `「」`，需要并列用 `、` `；`。
- **不要写 HTML 实体**（如 `&copy;`），直接用字符（`©`）。这是表现层的东西。
- **空数组直接省略**，渲染层已用 `|| []` 兜住。
- **换行统一用 LF。** 批量生成后检查一遍（Windows 上的脚本工具默认可能写 CRLF，之后再用别的工具打补丁还会在同一文件里混出两种换行）：

```js
const s = fs.readFileSync(f, 'utf8');
console.log(f, (s.match(/\r\n/g) || []).length ? 'CRLF' : 'LF');
```

- 文件头保留字段说明注释——它是这份数据唯一的自文档。

### 批量编辑

> ⚠️ **不要在 shell 里用正则批量改数据文件。** 内嵌 heredoc / `-e` 参数会把正则里的反斜杠转义吃掉（`[\s\S]` 变成 `[sS]`），导致**静默失配**——一条都没改上，却看不出哪里错了。

稳妥做法：把一次性脚本**写成文件**再执行，用**字符串定位**（`indexOf`）而非正则；改完立刻用运行时加载复验，再把脚本删掉。

## 八、校验

**写完必须跑校验，不要靠肉眼。** 错误以两种方式逃逸：

- **整页空白**：数据文件里任何一个语法错误都会让整个脚本不执行——不是错一条，而是列表、地图、筛选全都没有。
- **静默错位**：坐标落到别处，页面照常渲染，只有真去用的人才会发现。

### 数据校验

用运行时加载数据文件（Node 的 `vm` 等），**加载成功本身就是最强的语法检查**。逐条断言：`id` 唯一且仅字母数字、`lat`/`lng` 为数字且落在目标区域内、`tags` 非空、必填字符串字段齐全、`review` 必有 `src`、所有字符串不含 `<>`。

### 卡片片段长度自检

数据合法不等于**显示**合法。列表卡片的三个小标签各只取第一个分隔符之前的部分，写超了就断尾，而校验字段完整性是查不出来的。批量写完必须机械扫一遍：

```js
const brief = (v, seps) => String(v == null ? "" : v).split(new RegExp("[" + seps + "]"))[0].trim();
const SPEC = { area: "·", fee: "；;，,", hours: "（(；;" };   // 必须与渲染层的 brief() 调用一致
// 逐条逐字段：brief(值, SPEC[字段]).length > 13 即需改写
```

阈值按卡片宽度定。批量写入时这类超长往往**不是个别笔误，而是整批没按约定书写**，因此要当机械项全量扫。改写方向永远是「把短摘要提到分隔符之前」，**不是删信息**：细节移到分隔符后，详情面板照常显示全文。

### 冒烟测试

用桩顶掉地图库与 DOM，把渲染逻辑执行一遍，断言：标记数 == 卡片数 == 数据条数、图例标签数 == 实际用到的标签数 + 1。**多份数据要逐个跑，别只测第一个。**

### 校验脚本自身会误判

1. **`\s` 会匹配换行**——跨行匹配会把干净文件误报为「含样式属性」。要匹配横向空白请用 `[^\S\n]`。
2. **只数容器、不查内容**——数了「有多少个小标签」却没检查里面的 SVG 有没有实际图形，会漏掉「图标全空」这类真 bug。检查图标必须验证 SVG 内含 `path`/`circle`/`rect`。
3. **测试桩不还原浏览器行为**——桩的 `closest()` 对所有选择器返回同一对象、`location.hash` 不规范化、改 hash 不触发 `hashchange`，都会把「代码没跑」误判成「代码有 bug」。**桩必须还原真实语义。**

### 分层自检

分层架构会随时间腐化：一开始干净，改着改着框架里长出样式、逻辑里混进数据。定期检查**每层只含本层内容**：框架层无内联样式与数据赋值，逻辑层无地名与坐标字面量，样式层无 JS 语法，数据层无函数与 HTML。

**注意区分「写死的样式值」与「运行时变量注入」**：`style="--变量:${运行时取值}"` 合法（规则在 CSS、值按条目注入），`style="padding:28px;color:#9c9cb0"` 才是表现层漏进逻辑层。找字面量，不要一律禁 `style=`。

### 死代码与重复定义

同一份信息写两遍、改一处不生效，是最隐蔽的不一致。扫这几项：

- **图标**：已定义却从未被引用的（常见于框架已内联了同一图形）。
- **CSS 变量**：`:root` 里定义了，却既没被 `var()` 引用、也没被脚本读取。
- **跨层重复的数值**（如尺寸同时写在 CSS 变量与 JS 字面量里）。**做法是让脚本读 CSS 变量**，而不是两边各写一份。

## 十、维护

数据腐烂很快，每隔几个月过一遍：

- **营业时间、票价**：最易变动。
- **结业/搬迁**：处理范式是**保留条目但显著标注**——名称加标记、费用写「已关闭」、首句警告，并给出仍在营业的替代选项。既避免用户白跑，也保留历史信息。
- **展会/季节活动**：档期每年变，必须核对当年公告。
- **来源转载**：引用第三方平台的评语与评分需注意版权与平台条款，评分数字也会随时间失真。
